# Workflow C 详细技术文档（AI 真人口播带货）

> SKILL.md 已给"用大白话说"和当前可用度说明。本文件是**完整5阶段管线**+**贴图合成方案**+**数字人衔接**的详细技术参考。

---

## 定位

- **输入**：产品多角度视频/图
- **输出**：一位**真人主播（可来自用户提供的参考照，或由 AI 生成虚拟主播）**在指定场景（直播间等）口播介绍该产品的成片
- **与 A/B 的根本区别**：A/B 的输入核心是"人脸/动作"，**C 的输入核心是"产品"**；C 的主播身份**默认 AI 生成虚拟主播，若用户提供主播参考照则以该照作口播人物身份源**

## 阶段 C0：需求解析与素材就位

### 1. 解析用户自然语言 → 抽取 5 要素

| 要素 | 例 |
|------|------|
| 产品品类 | 漱口水 / 化妆品 / 数码产品 |
| 场景 | 直播间 / 桌面 / 户外 |
| 人设 | 女性主播 / 年轻男主播 / 资深讲解 |
| 景别 | 半身 / 特写 / 全身 |
| 卖点侧重 | 功能 / 价格 / 情感 / 对比 |

例："一位女性在直播间介绍这款漱口水" → 产品=漱口水；场景=直播间；人设=女性主播；景别=半身；卖点=待 C2 提炼

### 2. 主播身份源判定（关键）

- **用户提供主播参考照** → 该人物即口播视频的出镜人物（人脸+整体造型按 B-0 确认）。该照作为：
  ① 对口型数字人（腾讯智影 / HeyGem）的形象源
  ② 多参考生成（Seedance/Kling）的 ID 锁定源
- **未提供照** → AI 生成虚拟主播，人设由 C2 人设库按需求定

### 3. 素材 ASCII 化

产品多角度视频复制为 **ASCII 文件名**（如 `product_raw.mp4`）。⚠️ 同 A/B 坑点：cv2 读不了中文路径。

## 阶段 C1：产品资产提取

```bash
python scripts/product_extract.py \
  --video product_raw.mp4 \
  --out product_images/ \
  --count 5                # 抽取5张参考图
```

自动挑【清晰+正光+角度多样】的产品参考图集。

## 阶段 C2：场景推荐 + 人设匹配

- 场景推荐：AI 根据产品品类与用户/客户需求**主动推荐 2–3 个候选**，用户从中选择（决策门 C-2）
- 人设库：按性别/年龄/风格/服装匹配

## 阶段 C3：口播话术生成

输入：产品图 + 场景 + 人设 + 卖点
输出：四段式话术（开场钩子 → 痛点引入 → 产品介绍 → 行动号召）

## 阶段 C4：贴图合成 + 数字人对口型

### 方案 1（推荐）：真产品贴图合成 + AI 人物场景

- 关键展示镜头用用户上传的**真实产品图**做贴图/合成（保 logo、文字 100% 不变形）
- 人物/场景/动作由 AI 生成
- ⚠️ **当前状态**：方案已文档化，**需用户实际跑真实产品视频抽检贴图接缝**（当前环境不能读图，未端到端验证画面）

### 方案 2：TTS 配音 + 对口型数字人

- 文案 → TTS 人声 → 驱动主播对口型
- 推荐通道：腾讯智影（SaaS，需账号）或 开源 HeyGem（可本地部署）
- ⚠️ **当前状态**：需平台账号/本地部署，**本技能不包含对口型数字人本身的实现**

## 阶段 C5：成品验收

- 产品一致性：logo/文字/瓶身/包装是否变形
- 口播同步：口型与音频是否同步
- 时长：与预期相符

## 常见问题

**Q: 我的 logo 总是变形怎么办？**
方案1的"贴图合成"就是为解决这个问题设计的——真人产品图贴入 AI 场景，logo 不变形。详见阶段 C4 方案1。

**Q: 数字人平台要付费吗？**
- 腾讯智影：SaaS，按用量计费
- HeyGem：开源免费（需算力/部署）
- 具体选哪个看预算和技术能力

**Q: 没有主播参考照能用吗？**
可以，AI 会生成虚拟主播（人设由 C2 人设库按需求匹配）。但效果通常不如提供真实参考照。
